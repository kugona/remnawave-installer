# Архитектура

Этот документ описывает архитектуру и сценарии установки, поддерживаемые remnawave-installer.

## Сценарии установки

### Вариант 1: Два сервера (Панель и Нода раздельно)

Рекомендуется для надёжности и гибкости.

**Сервер Панели:**
- Remnawave Panel
- Subscription-Page
- Angie (для панели и подписок)
- PostgreSQL, Redis

**Сервер Ноды:**
- Remnawave Node (с Xray)
- Angie для домена Selfsteal

**Настройка DNS:**
- Домены панели и подписок → IP сервера панели
- Домен Selfsteal → IP сервера ноды

**Порядок установки:**
1. На сервере панели: выберите "Panel Only". Сохраните публичный ключ (`SSL_CERT="..."`)
2. На сервере ноды: выберите "Node only". Введите домен selfsteal, IP панели и сохранённый ключ

### Вариант 2: Всё-в-одном (Панель и Нода на одном сервере)

Упрощённый вариант для тестирования или малых нагрузок.

**Один сервер содержит:**
- Remnawave Panel, Node, Subscription-Page
- Angie, PostgreSQL, Redis

**DNS:** Все три домена (разные!) → IP этого сервера

### Маршрутизация трафика (режим Всё-в-одном)

```
Клиент → Порт 443 → Xray (локальная Remnawave Node)
                      ├─ (VLESS прокси-трафик) → Обрабатывается Xray
                      └─ (Не-VLESS трафик, fallback) → Angie (127.0.0.1:9443, обычный TLS)
                                                        ├─ SNI: Домен панели → Remnawave Panel (порт 3000)
                                                        ├─ SNI: Домен подписок → Subscription Page (порт 3010)
                                                        └─ SNI: Домен Selfsteal → 403 Forbidden
```

> **Примечание**: Xray передаёт соединения в Angie без PROXY protocol (`xver: 0`), поэтому за Xray панель и страница подписок видят адрес клиента как `127.0.0.1`.

> **Примечание**: В режиме Всё-в-одном, если остановить ноду или сломать конфиг Xray, панель и другие веб-сервисы станут недоступны через доменные имена.

## Структура директорий

### Установка панели (`/opt/remnawave/`)
```
/opt/remnawave/
├── .env                    # Переменные окружения панели
├── docker-compose.yml      # Сервисы панели
├── credentials.txt         # Сгенерированные учётные данные
├── Makefile                # Управление сервисами
├── angie/
│   ├── angie.conf         # Базовая конфигурация
│   ├── conf.d/            # ACME-клиенты, блоки server, защита панели
│   ├── snippets/          # Ответы с ошибками и location
│   └── docker-compose.yml
├── subscription-page/
│   └── docker-compose.yml
└── node/                   # (только Всё-в-одном)
    ├── .env
    └── docker-compose.yml
```

### Отдельная установка ноды (`/opt/remnanode/`)
```
/opt/remnanode/
├── .env
├── docker-compose.yml
├── Makefile
└── selfsteal/
    ├── angie.conf
    ├── conf.d/
    ├── snippets/
    └── docker-compose.yml
```

## Защита доступа к панели

### Секретная ссылка (403)
- Доступ по URL с секретным ключом: `https://panel.example.com/auth/login?<случайное имя>=<секрет>`
- Angie устанавливает cookie при первом посещении
- Без валидного cookie или параметра любой путь возвращает `403 Forbidden`

### Basic Auth (401, рекомендуется)
- **Двухуровневая аутентификация:**
  1. HTTP Basic Auth в Angie (стандартное окно браузера, без MFA)
  2. Вход в Remnawave Panel
- Без учётных данных любой путь возвращает `401 Authorization Required`
- После успешного входа Angie устанавливает сессионный cookie, потому что интерфейс панели использует заголовок `Authorization` для своих API-токенов
- Внешние API-клиенты должны передавать сессионный cookie из браузера или подключаться локально к порту 3000

### Сертификаты
- Встроенный ACME-модуль Angie получает отдельный сертификат Let's Encrypt для каждого домена через HTTP-01 и обновляет его за 30 дней до истечения, без cron и перезапусков
- Порт 80 должен быть доступен из интернета, в том числе для обновлений. Проверка не идёт через Xray, и его запуск для неё не нужен. Angie слушает и IPv6, если он есть на сервере
- Сертификаты хранятся в Docker-томе `remnawave-angie-acme`; `--keep-angie-data` сохраняет его при переустановке
- Установки на версии с Caddy нужно переустановить: изменился адрес fallback в Xray

## Сетевая конфигурация

### Открытые порты
| Порт | Назначение |
|------|------------|
| 80/tcp | Angie HTTP, проверка ACME |
| 443/tcp | Angie HTTPS / Xray |
| 22/tcp | SSH (или ваш порт) |
| 2222/tcp | API ноды (ограничен) |

### Ограничения порта 2222
- **Всё-в-одном**: Открыт только для 172.30.0.0/16 (подсеть Docker)
- **Отдельная нода**: Открыт только для IP панели
